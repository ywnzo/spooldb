# SpoolDB 0.4.26

Acceptance testing of 0.4.25 found that its mixed setup/configuration tool could trigger a second permission check for already-approved retrospective reads. Dedicated history_read and history_complete tools now describe those operations accurately, while retaining the same per-checkout explicit-consent and pending-job guards. They cannot authorize analysis or change sharing. Existing setup actions remain compatible.

A private lifecycle checkpoint can now advance a shared task and complete it without a false revision conflict. Concurrent changes by another client are still rejected and raw private checkpoint text is never exported.

The reviewed hook runtime is unchanged from 0.4.25. This patch does not bypass hook review or a rejected history read.
