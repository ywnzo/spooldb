# SpoolDB 0.4.22

Repository onboarding now shows the existing shared project and asks the user to join it instead of offering duplicate creation. This applies to Codex first-prompt guidance, plugin setup, the web approval flow, and spool init. A create request encountering a match returns a join choice without connecting or capturing until the user approves.

The relay rejects duplicate repository creation and linking the same repository to another project. Original creation retries remain idempotent; competing requests cannot create additional projects. Clients without access must obtain an invitation. Existing project rooms, memory, sharing settings, credentials and legacy associations are preserved.

The onboarding hook changed to check matching projects before asking its question. Codex requires review of changed hook code once; hook trust is never set automatically.
