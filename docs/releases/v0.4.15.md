# SpoolDB 0.4.15

Relay update backups now have automatic retention. The default keeps the newest three backups for up to 30 days, while always protecting the latest successful rollback backup and any backup needed by an interrupted transaction.

Cleanup runs during daily update checks (including checks where no update is available), after successful updates, after restored rollbacks, and after recovery. Existing v0.4.13/v0.4.14 snapshots are supported. Unknown folders and symlinked directories are skipped; corrupt recovery references block deletion. Cleanup failures are recorded without rolling back a healthy update.

Preview or run retention manually:

```sh
sudo spool update cleanup --dry-run
sudo spool update cleanup
```

`sudo spool update status` shows the policy and last cleanup result. The default needs no additional opt-in once relay updates are enabled. See [updates](../updates.md) for configurable limits and recovery.
