# SpoolDB v0.4.36

Repositories now keep their own relay and shared-project binding. Adding a saved connection no longer changes where other repositories send memory. Existing connections and memory are preserved.

- Codex selects memory by the repository it is working in, including nested repositories and submodules.
- Unconnected repositories offer explicit connection and create/join choices. Existing repository matches offer joining instead of duplicate creation.
- Older relays are detected before creating projects. Codex can offer an authenticated host update; Cloudflare updates use the existing deployment credentials and configuration. Existing matching projects remain joinable.
- Mid-chat context includes a usable task ID and revision, plus clearer finding and handoff instructions. Corrected the packaged MCP launcher version.
- CLI and web setup select a connection per repository. Lifecycle status distinguishes observed hook delivery from capture configuration.

Validation included a fresh desktop Codex chat using an ordinary pricing-bug prompt: it retrieved existing context and saved a finding, linked handoff and completed task without corrective follow-ups. This is an observed successful flow, not a guarantee that every model run will save useful memory.

Review changed hooks when Codex requests it and start a fresh chat after updating. Code stays in Git; shared memory stores references and explicitly approved memory categories.
