# SpoolDB v0.4.32 — quieter background sync

Idle project sync checks now back off to five minutes and skip network access before that deadline. New memory bypasses the timer on the next capture cycle; file-only changes do not wake relay memory sync. Offline retries also back off, and explicit agent reads and writes remain immediate.

Duplicate state requests are removed. Reads use sharing metadata returned with the authorized memory response; writes continue to check fresh sharing policy. Project credentials remain isolated.

The memory UI backs off from 15 seconds to two minutes while unchanged. Hidden tabs stop scheduled polling and refresh on return. Stable retrieval and maintenance settings refresh every two minutes, keeping faster progress checks while loading or updating.

A simulated idle day uses at most 300 project state checks versus approximately 43,200 previously. Validated with 281 passing tests, two environment-dependent skips, type checking and browser navigation checks. Clients must update to receive these reductions; updating the relay alone does not change older clients.

Release validation also fixes a timing-sensitive maintenance test to select its job by ID when jobs share the same creation timestamp. v0.4.31 was not published because that test failed in CI.
