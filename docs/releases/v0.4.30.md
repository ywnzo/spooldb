# SpoolDB v0.4.30 — Cloudflare embeddings

Self-hosted relay owners can choose Cloudflare Workers AI BGE-M3 in Settings → Search & memory. Enter an Account ID and scoped API token, test the connection, then explicitly approve external processing to enable it. Local embeddings remain the default.

Tokens stay in private relay settings tables, outside replicated project history, and are never returned in status responses. Owners can replace or remove them. Relay backups contain credentials and must be protected. Cloudflare receives indexed passages and search queries when enabled.

Stored record vectors are reused across restarts, repeated query embeddings are cached, and API failures fall back to keyword retrieval. Requests use a fixed HTTPS endpoint, refuse redirects, validate responses, and have bounded timeouts. Switching away from Cloudflare stops and cancels its active provider.

Validated with 277 passing tests and two environment-dependent skips, type checking, and a browser setup/disconnect flow using a simulated Cloudflare service. No production memory was transmitted during testing. Existing project connections and local-model settings are preserved.
