# SpoolDB v0.4.45

Existing installations keep working when updating from the older state-folder layout.

- Reuse a primary project stored at the state-folder root instead of treating it as a fresh desktop installation. Existing project identities, relay grants, saved connections and memory stay in place.
- Keep memory and management available when an optional source snapshot exceeds its size limit. The capture error remains visible in service status, and normal capture retries can recover after the source is corrected. Snapshot safety limits and sharing settings stay unchanged.
- Add a regression test that restarts an enrolled legacy installation, verifies unchanged connection files, reads existing shared memory, writes new shared memory and checks recovery and a second restart.

The plugin bundle includes these fixes. Update SpoolDB through the existing Codex marketplace connection; no project reconnection or memory reset is required.
